# 端到端证据

[English](E2E.md) · [中文](E2E_zh.md)

`release_readiness` 声称了什么，背后真正的依据是什么。`kicad-cli reference`
给出声称，`doctor` 里有一项检查必须与之一致；这一页是两者的依据。

## 当前等级：`stable`

| 证据 | 用于 | 状态 | 在哪儿 |
|------|------|------|--------|
| 功能契约覆盖 100% | 任何可发布等级 | **已验证** | `tests/test_contract.py`、`tests/test_fcc_guard.py` |
| 上游 mock / 契约测试 | `beta` 和 `stable` 都要求 | **已验证** | `tests/test_mock_upstream.py` |
| 记录在案的实机 smoke / E2E | `stable` | **已验证** | [`evidence/live-smoke-1.0.0.md`](evidence/live-smoke-1.0.0.md) |
| 产物本身能启动 | 只要发布就必须 | **已验证** | `scripts/smoke_binary.py`，记在同一份文件里 |

## 为什么有两种测试

实机测试和 mock 测试不是通往同一个地方的两条路。

**实机**测试启动真的 `kicad-cli`，它再启动真的 KiCad 解释器和二进制，跑在 KiCad
自带的演示工程上（先复制到临时目录）。没有任何录制或回放。它们证明命令能用。

**mock** 测试把两个 KiCad 边界——官方二进制和自带解释器——换成能按指令失败的
替身。它们存在的理由是：真的 KiCad 不会按需拒绝启动、不会退出 0 却什么都不写、
不会挂死、不会吐垃圾、更不会前两次失败第三次成功。而这些路径恰恰决定了一块健康的
板子会不会被报成坏的，没有别的办法能走到。它们还能在没装 KiCad 的机器上跑——
那里所有实机测试都会跳过。

两个边界都是按环境变量给的绝对路径解析的，这正是替换能够成立、又不必在产品代码里
开口子的原因。

## 测试到底查了什么

- **契约。** `reference` 里的每条命令都带 `KICAD_CLI_STRICT` 跑一遍。严格模式下
  信封拒绝输出 schema 没声明的字段，声明了却缺失也会失败。它第一次跑起来就抓到
  `board audit` 声明了三个从不输出的字段，又漏掉四个一直在输出的。
- **覆盖。** 守卫不相信"测试存在"这种说法。它读 CLI 在运行期写下的派发留痕，
  只要有一条公布的命令没被真正派发就失败。对着替身跑的那些**故意不计数**，
  所以覆盖率没法拿假上游凑。用变异验证过：让一个测试跳过，它会点名那条漏掉的命令。
- **写门禁。** 写命令在副本上走完整的 `--dry-run` → `--confirm` 流程，并读回结果。
- **Skill。** `SKILL.md` 拿活注册表校，因为 CLI-SPEC §13 把它算作公开契约。
  它无法公布一条不存在的命令、字段、选项或安装目标。

## 测源码不等于测产物

测试跑的是 `python -m kicad_cli.main`。用户装到的是一个冻结的单文件二进制：没有包
上下文、载荷以数据形式随行、IPC 客户端从 vendored 目录冻进去。这是两个不同的程序。

这个缝不是假想的：这个仓库构建出的第一个二进制，在第一个相对导入上就崩了，每条命令
都打印 Python 回溯而不是信封——而测试全绿。`scripts/smoke_binary.py` 跑的是产物本身：
它必须能启动、stdout 恰好一个可解析信封、带着载荷和 changelog、报出的版本与
`package.json` 一致、未知命令要变成信封而不是回溯。发布流程在打包任何东西之前先跑它。

## 行为覆盖面，对照 CLI-SPEC §11

| 类别 | 由谁覆盖 |
|------|----------|
| 成功路径 | 实机（全部命令）+ mock |
| 输出 schema | 严格模式，实机与 mock 都有 |
| 参数校验 | 参数门禁、未知选项、未知层名 |
| 配置失败 | `board live` 在 API 不可达时 |
| 上游失败 | mock：非零退出，以及退出 0 却没有产物 |
| 超时 | mock：一个活得比调用方超时更久的替身 |
| 重试恢复 | mock：失败两次再成功，断言确实恢复了 |
| 协议噪声 | mock：SWIG 噪声，含一行以 `{` 开头的假货 |
| 空结果 | mock：空网表被拒绝，而不是报成 `add: 0` |
| 退出码 | 对着生成的契约表断言 |
| stdout/stderr 边界 | stdout 恰好一个信封，每次 mock 调用都断言 |
| 认证、权限 | **不适用**——根本没有凭据 |
| 分页、限流 | **不适用**——没有服务，没有分页结果 |

## `stable` 在这里**不**意味着什么

记录在案的那次实机运行只有一个平台、一个 KiCad 版本：Windows、KiCad 10.0.6。
背后没有第二台机器，也没有 CI，因为 CI 上没有 KiCad。mock 测试到处都能跑、覆盖
失败路径，但它没法告诉你 KiCad 10.0.7 写出来的文件格式还是一样的。

另一件事：大多数命令压在 `pcbnew` 的 SWIG 绑定上，而 KiCad 已经把它排进 11 版
移除计划。[`COMPATIBILITY_zh.md`](COMPATIBILITY_zh.md) 列了这会波及哪些命令、
各自需要换成什么。

这两条都没有被等级藏起来——它们就写在 `release_readiness.reason` 里，
agent 在信任这个等级之前会读到。

## 复现

```bash
pip install -e ".[dev]"
pytest tests/ -v --tb=short
```

装了 KiCad 就是全量。没装的话，实机测试跳过、mock 测试照跑——那个子集过了是实打实
的结果，不是默认通过。
